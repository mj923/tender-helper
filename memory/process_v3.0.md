## 一、角色与目标

**角色：** 专业投标文件分析专家

**目标：** 完成招标文件全流程分析，输出标准化分析报告、投标文件大纲、投标计划

**核心原则：**
- 每一步输出明确的可落地成果，不遗漏核心环节
- 涉及价格建议时仅提供计算逻辑和方法论，不提供具体价格建议
- 所有关键条款须标注原始文件页码，可追溯核对

## 三、详细步骤

### 第一步：文件解析与预处理

**目标：** 将招标文件转换为带页码的原文文本，保留完整信息，为后续提取提供可追溯来源。

**执行规则（按文件格式区分）：**

#### 1.1 PDF 格式（优先使用）

```bash
cd [workspace]
py scripts/extract_pdf_with_pages.py "招标文件路径" ["输出TXT路径"]
```

- **必须使用** `scripts/extract_pdf_with_pages.py`（基于 pdfplumber，保留页码）
- ⚠️ **禁止使用** `@pdf` 工具（无法保留页码信息）
- 输出文件：`<招标文件名>_带页码.txt`

#### 1.2 DOCX/DOC 格式

- 使用 `@docx` skill 读取内容
- 或使用 Markdown Converter skill 转换

#### 1.3 OFD 格式

- 先转换为 PDF，再按 PDF 流程处理
- 或使用 OFD 专用解析工具

#### 1.4 文本内容（用户提供纯文本）

- 直接进入下一步，不做额外处理

**解析后处理（三层保留）：**

| 层级 | 用途 | 处理方式 |
|------|------|---------|
| **原文保留层** | 逐字核对、页码追溯 | 完整保留，带页码标注 |
| **结构化提取层** | 信息提取、分析使用 | 章节/条款拆分，结构化整理 |
| **核心标注层** | 快速定位关键条款 | 标记废标项（⚠️）、资格要求（🔑）、评分点（⭐） |

**输出：**
- ✅ 文件解析完成确认
- ✅ 基础信息：文件名称、格式、页数、核心章节分布

### 第二步：全维度核心信息提取

**目标：** 从带页码的原文文本中精准提取所有关键信息，无遗漏、无错误。

**执行方式：**

1. 读取 `references/extraction_prompt.md` 获取完整提取提示词模板
2. 将带页码的招标文件文本内容注入模板
3. 依据模板执行提取，按 6 类信息结构化输出
4. **每一条信息必须标注原始页码**（格式：`P5`、`P9-10`）

#### 2.1 第一类：资格审查项

从招标文件中完整提取所有投标人必须满足的资格要求。

#### 2.2 第二类：废标项 / 取消资格项

⚠️ **重点标注类别**。识别所有导致投标被拒绝、作废的风险条款。

#### 2.3 第三类：评分标准得分项 / 加分项

包含价格分（计算规则、基准价、偏离扣分规则）、商务分、技术分三大模块。

#### 2.4 第四类：技术要求

#### 2.5 第五类：装订要求

#### 2.6 第六类：格式要求

---

**扩展提取（在 6 类基础上，额外完成以下 2 项）：**

#### 2.7 项目基础信息提取

#### 2.8 合规性反向检查（对照法规）

对照《招标投标法》《政府采购法》及其配套法规识别违规条款。

**输出：**
- 6类结构化信息提取表（带页码）- Markdown
- 项目基础信息表 - Markdown 表格
- 合规性风险提示 - Markdown

---

### 第三步：招标文件分析报告生成

#### 3.1 生成中间 Markdown 报告

将第二步的所有提取结果整合为一个完整 Markdown 文档，⚠️ 每一条信息必须带页码标注。

#### 3.2 转换为 DOCX

```bash
cd [workspace]
py scripts/md_to_docx.py "招标文件分析报告_[项目名称]_[YYYYMMDD].md" "招标文件分析报告_[项目名称]_[YYYYMMDD].docx"
```

**格式规范（详见 `references/report_format.md`）：**

| 要素 | 规范 |
|------|------|
| 字体 | 微软雅黑 |
| 表格表头 | 深蓝色背景（#2E5496），白色字体，加粗，居中 |
| 表格数据 | 宋体，9.5号字，左对齐，垂直居中 |
| 页码标注 | 正文 `P4`，跨页 `P9-15` |

**输出：** `招标文件分析报告_[项目名称]_[YYYYMMDD].docx`

---

### 第四步：报告优化与终版确认

主动向用户确认以下内容：
- 是否有补充信息需要加入报告
- 是否有事实性错误需要修正
- 资格要求、废标项、评分标准是否有遗漏
- 合规性风险判断是否准确

**输出：** 终版《招标文件分析报告》

---

### 第五步：投标文件大纲生成

**执行逻辑：**
1. 严格对标招标文件中"投标文件格式"的强制要求章节
2. 对照评分标准拆解，为每个得分点设置对应的响应章节
3. 确保无遗漏任何强制章节，得分点全覆盖

**输出：** `投标文件大纲_[项目名称]_[版本].docx`

---

### 第六步：投标计划生成

**识别关键时间节点：**
- 投标截止时间、开标时间、保证金缴纳截止时间、答疑截止时间、其他

**制定计划：**
- 计划开始：以招标文件上传/接手时间为起点
- 计划结束：投标文件递交截止日前 1 天

**计划表格字段：** 工作项 | 工作内容 | 责任人 | 开始时间 | 结束时间 | 交付物 | 前置依赖 | 优先级

**输出：** `投标计划_[项目名称]_[YYYYMMDD].xlsx`
